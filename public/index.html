How it works

  1. Pipeline #1 — one Clocked /pipeline request: Protect (pii) masks the customer's personal data before it reaches the LLM; Guard (injection, source:"content") screens every retrieved passage and quarantines poisoned ones; Rerank says use / expand / skip per passage and answers a Decide-style coverage question; Compare finds passages that contradict each other so the outdated one is dropped.
  2. The LLM drafts a reply only from the passages TrustGate kept (or the bot hands off to a person when coverage is not_established).
  3. Pipeline #2: Verify (grounding) checks every sentence of the draft against the kept passages, and Protect catches personal data the draft copied from internal notes. Only supported, PII-free sentences are sent; everything else goes to the agent-review list.
